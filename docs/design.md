# 设计文档:口头消息在智能体之间传递时的信息损失测量平台

> 本文记录 2026-11-22 确认的设计决定。只写已经定下来的内容;没定的、没验证过的,都明确标出"未定"或"未验证",集中列在第 8、9 节。
> 本文只是文档,不含代码改动。

## 0. 先解释几个词

后文会反复用到这些词,先在这里说清楚。

| 词 | 意思 |
|---|---|
| 智能体 | 由大语言模型驱动的虚拟角色。它有自己的记忆,会和别的角色对话。 |
| 大语言模型(下文简称"模型") | 根据输入文字生成回复文字的程序,例如 DeepSeek。智能体"想什么、说什么"都由它生成。 |
| 一次运行 | 把仿真从头到尾跑一遍。 |
| 条件 | 一组实验设置的组合,例如"用某个模型 + 摘要 30 字 + 开反思 + 接力链 + 简单通知"。 |
| 因子、水平 | 因子是实验里人为改变的一项设置(如"摘要长度");水平是这项设置可取的值(如 30、100、300 字)。 |
| 完全交叉 | 每个因子的每个水平,都和其他因子的每个水平组合一遍,一个组合都不漏。 |
| 随机种子(种子) | 决定程序里随机部分的一个数字。同一个条件换不同种子重复跑几次,可以看出结果有多少是偶然波动。 |
| 摘要 | 智能体听完一段对话后,不存原话,而是存一段压缩过的概括。摘要长度就是这段概括的字数上限。 |
| 逐字原文 | 对话里一字不差的原话。 |
| 反思 | 智能体回看自己的记忆,归纳出新的想法,并把这个想法也存进记忆。 |
| 记忆整合 | 新内容写进记忆时,和已有的记忆比对,决定是新增、更新、标记冲突,还是不处理。 |
| 事实槽 | 把一条消息拆成若干条独立的事实(如时间、地点、人名)列成的答案表。打分时逐条检查某句话里还剩几条。 |
| 接力链 | 受控的传话方式:源消息 → 甲 → 乙 → 丙……每人只从上一个人那里听,再讲给下一个人。 |
| 自然相遇 | 不安排谁传给谁。智能体在地图上按各自的日程活动,碰到了才聊天,消息靠这些相遇传开。 |
| 基线 | 做对照时用来比较的那个"标准条件"。 |
| 混淆 | 两个因素同时在变,结果的差别说不清是哪一个造成的。 |

## 1. 研究问题

一条口头消息在智能体之间传递时,要经过四个环节:

1. **听到**:对方说的话,自己接收到了多少;
2. **存储**:听到的内容,写进记忆时留下了多少;
3. **取回**:下次要说话时,从记忆里找回了多少;
4. **转述**:找回的内容,讲给下一个人时说出了多少。

研究问题是:**每个环节各丢了多少信息,哪些条件会改变丢失的多少。**

定位上有三点已经确定:

- **主要贡献是测量平台本身**,即一套能把四个环节的损失分开测出来的工具。
- **测出来的数字只是用这个平台做的一次测量**,它依赖所用模型的版本;模型换了版本,数字可能不同。
- **不预设任何现象**。不事先假定会出现"涌现"(整体表现出个体没有的行为)、"自我纠错"(传错的内容后来被改对)或"像人"(与人类传话的规律相似)。看到什么就报告什么。

## 2. 平台

### 2.1 引擎

保留原型的仿真引擎(驱动智能体活动、对话、记忆的那部分代码),不重写。

### 2.2 测量底座

在引擎之上加一层**与场景无关的测量底座**("与场景无关"指换一张地图、换一批角色,这层代码不用改)。它在 [PR #1](https://github.com/Vigo222/fishing-village-generative-agents/pull/1) 中,写本文时该 PR 尚未合并。底座包含四点:

- **结构化事件日志**:每次运行把发生的事(谁对谁说了什么、谁往记忆里写了什么、谁取回了什么等)按固定格式一条条记下来。
- **跑后打分,对照事实槽**:运行结束后,另一个程序读日志,对照事实槽逐条判断每句话、每条记忆里保留了哪些事实。**事实槽智能体永远看不到**,只交给打分程序。
- **逐字原文只进日志**:原话只写在日志里供打分用;默认情况下智能体自己事后能读到的只有它存下的摘要。
- **模型失败则本次运行作废**:模型调用失败时,不再悄悄用一个替代值继续跑("静默兜底"),而是把整次运行标记为无效,不参与打分。

## 3. 核心实验:完全交叉的因子表

五个因子,完全交叉:

| 因子 | 水平数 | 水平 |
|---|---|---|
| 模型 | 2 | DeepSeek-V4-Pro;DeepSeek-V4-Flash |
| 摘要长度 | 3 | 30 字;100 字;300 字 |
| 反思 | 2 | 开;关 |
| 传播方式 | 2 | 接力链;自然相遇 |
| 消息难度 | 2 | 简单通知(4 条事实);困难通知(10 条事实) |

- 条件数:2 × 3 × 2 × 2 × 2 = **48 个条件**
- 每个条件 5 个随机种子:48 × 5 = **240 次运行**
- 每次运行 **10 个智能体**

## 4. 单因子对照

从基线出发,每次只改一项,每项跑 5 次,共 4 项 × 5 = **20 次运行**:

| 对照 | 改了什么 | 说明 |
|---|---|---|
| 可读原文 | 智能体可以读到逐字原文 | 默认只能读摘要 |
| 关闭记忆整合 | 记忆整合关掉 | |
| 20 个智能体 | 同一张地图上放 20 个智能体 | 日志里记录相遇次数,这样可以把"人多"和"碰面更频繁"这两件事分开看 |
| 八卦消息 | 用一条含 10 条事实的八卦消息 | 与困难通知比较 |

**总计:240 + 20 = 260 次运行。**

核心因子表中的哪一个条件作为基线:未定(见第 9 节)。

## 5. 消息材料

- **简单通知**:含 4 条事实。
- **困难通知**:含 10 条事实,其中包括容易混淆的日期/数字、一个不常见的人名、一条例外情况。
- **两条都是"通知"这一种体裁。** 这样两者的差别只在难度上,难度不会和体裁混淆。
- **消息是自己写的,不用经典材料。** 经典材料模型可能在训练时见过,能直接背出来,那样测到的就不是传递中的损失。
- 对照里的八卦消息含 10 条事实,用来和困难通知比较(同样 10 条事实,体裁不同)。

三条消息的具体文字和各自的事实槽:未定。

## 6. 演示界面

演示界面分三层:

1. **接力链总览**:把接力链画出来,每个节点(链上的一个智能体)的颜色表示到它这里还剩多少信息。
2. **节点详情**:点击某个节点,看它听到了什么、存了什么、取回了什么、说了什么;丢掉的部分用红色标出。
3. **损失汇总**:每个环节各丢了多少的汇总。

展示方式上的要求:

- 内容分块;
- 一次只展开一块;
- 每个术语都给出解释。

提出这个要求的原因:作者本人说自己看的时候注意力容易分散。

## 7. 应用价值(论文里怎么写)

- **正文里写的应用价值**:多智能体工程。多个智能体协作时要互相交接信息,这个平台可以测出交接中丢了什么。
- **放在"未来工作"里**:谣言研究、心理学的传播链实验、社会学、游戏。
